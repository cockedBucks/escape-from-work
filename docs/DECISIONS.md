One line per decision: `Dnnn (date, phase): decision — why`. Newest at the bottom.
Big decisions that change ARCHITECTURE or GAME_DESIGN need the human's OK first.

- D004 (2026-10-04, kit): One lobby per server instead of room codes — one office, one server; fewer edge cases.
- D005 (2026-10-04, kit): Tracks are spline data with zones as lap fractions — tracks can be written and validated as text by agents.

- D008 (2026-10-04, kit): League stored as an atomic JSON file — no database server, no native modules, installs on Windows without build tools.

- D031 (2026-10-04, P1.1): Shared basics. RNG is mulberry32 with a single 32-bit `state` (saved in snapshots, hashed for replays). With forward = (sin yaw, cos yaw), a bigger yaw turns the car LEFT; the sim steers right by lowering yaw. The car balance limit (0.92–1.08) lives in `cars.json` as `statRange` and the schema enforces it. Car color is not in `cars.json`: team color comes from the slot (ART_STYLE §3). Track zones may not cross the start line (`from < to`); split them if needed. Quality presets also carry the /shots performance budgets so they live in one place.
- D032 (2026-10-04, P1.2): Tracks use a centripetal Catmull-Rom spline resampled at even arc length (`track.sampleSpacing` = 2 m). Zone and start positions are fractions of loop length from control point 0 (lap progress = that minus `start.at`). Walls are offset polylines at ±width/2; `track:check` rejects widths below `track.minWidth`, curves tighter than half the road width and any crossing walls. New tuning section `track`. `scripts/track-check.mjs` loads the shared TypeScript via `tsx/esm/api` `tsImport` (tsx is already a dev dependency). Test Loop: 931 m kidney loop with a U-shaped hairpin dent (radius ~14 m), a ramp on the opening straight, a slick on the right sweeper.
- D033 (2026-10-04, P1.3): Car physics v1. Sim input is `{ steer -1..1 (+1 = right), gas, brake, respawn }`; gas+brake together = brake (the drift tap comes in P5). Brake when stopped drives in reverse. Coasting uses `car.drag` (proportional) + new `car.rollingResistance` (constant) so cars come to a full stop. Grip decays sideways speed with exp(-grip·dt) so it does not depend on tick rate. No engine, brakes or steering in the air. A ramp launches only on entering its zone, scaled by forward speed / base top speed. Wall hits below `car.wallHitMinSpeed` (scraping) cost no speed and send no event. Checkpoints count only in order; respawn uses the last one. A grounded car more than `race.offTrackRespawnDistance` outside the road respawns by itself. Timers are stored as tick numbers, not seconds, so they never drift. Seeded RNG is not used by the sim yet; `step(world, inputs, cfg)` gains it when items need it.
- D034 (2026-10-04, P1.4): Bot = pilot half (`botSteer`: aim at a centerline point `lookAheadBase + speed × lookAheadTime` ahead) + engineer half (`botPedals`: corner speed sqrt(cornerAccel × radius) planned back with `brakePlanDecel` over `planDistance`; respawn after `stuckSeconds` below `stuckSpeed`). Bots steer analog (-1..1); quantizing to keys is a P2.5 concern for WebSocket bots. A lap = a gate-0 checkpoint after all gates in order. Golden: Test Loop lap 1 37.4 s, flying laps 36.0 s (windows ±~5%); 2-car 1-lap hash `a71bcb87`. Hash = FNV-1a over float64 bits (V8 math functions are the same on every OS). No lap-time target check in track:check yet: a target needs a per-track field (format change), revisit with The Office in P7. Also: `/next` with no argument now keeps going across tasks and phases, stopping only at HUMAN GATEs or decisions (human request).
- D035 (2026-10-04, P1.5): Server sim uses Colyseus 0.18 `setFixedTimestep` (framework accumulator with a catch-up cap) instead of our own loop; the sim still steps with `cfg.sim.dt`. Room logic lives in a Colyseus-free `RaceSim` class (unit-testable); the room only wires messages, rate limits and state sync. Car id = player's sessionId for now; all solo cars spawn on the start line (no car collisions until the race grid in P3). Synced car fields: x, z, y, yaw, speed, steer, progress, respawning, ghost (float32). Input rate limit: token bucket 70/s, burst 20 (`net.inputRatePerSec`, `net.inputBurst`). Default track `test-loop` is a server constant until the lobby picks tracks (P3).
- D036 (2026-10-04, P1.6): Client rendering. `chase` and `track-overview` run a local 4-bot race with the shared sim and freeze it (chase at 6 s), so screenshots are identical every run; the live game uses the same `Game` renderer fed by `ServerCarSource` (snapshot buffer, drawn `net.interpDelayMs` in the past). Visual-only numbers (palette, greybox sizes, box car, light, overview framing) live as named constants in `packages/client/src/render/look.ts`; chase-cam feel is in a new tuning section `camera` so F2 can tune it. Config files are bundled into the page with `import.meta.glob` (offline). Sky/fog use the glass blue (#BFE3F2) so the horizon reads against the sand ground. Flat road markings use polygon offset; the overview camera uses tight near/far planes. Curbs are drawn only on curves (|curvature| ≥ 1/60 m). The server reports a smoothed `tickMs` in the state for the F3 overlay. Placeholder box car: 6 draw calls, ~300 triangles (P7 car kit replaces it).
- D037 (2026-10-04, P1.7): Live tuning. One `LiveConfig` per server holds tuning, cars and track and notifies rooms; tests pass a temp copy of `config/` so they never touch the real files. Panel edits go through HTTP (`POST /dev/tuning`, proxied by Vite) rather than a room message, so live preview and Save share one validated path; the server echoes the result to every client as `tuning`, and the panel ignores echoes for 600 ms after a local edit so a dragged slider never jumps. The client accepts HMR for tuning.json/cars.json (no page reload while tuning); track edits reload the page. Changing `sim.dt` needs a server restart (the tick rate is fixed when the room starts). The request schema lives in shared (`TuningPostSchema`) because zod is approved for shared only.
- D038 (2026-10-04, P1.8): Phase 1 review fixes. Respawn fires once per R press (server tracks held → pressed edges), so holding R or resent messages never respawn-loop. Clients resend held controls every `net.inputResendMs` (250 ms) so a lost message never leaves a key stuck. Live changes to `sim` or `track.*` are kept until a server restart (logged). The F2 panel's hidden sections always follow the server, so Save cannot write back stale copies. `car.topSpeed` is capped at 100 m/s (wall tunneling safety). Hot-reloaded tracks must pass `checkTrack`. Rate limiters follow live tuning. Interpolation snaps cars that move > 15 m between snapshots (respawn). Car bodies are transparent only while ghosted. `tickMs` is synced in 0.1 ms steps. Deferred: tick-based snapshot timing (P2.6), dev endpoint LAN exposure (accepted in dev).
- D039 (2026-10-04, P2.1): Seats. A car slot has Pilot + Engineer seats, or one player takes it as Solo (blocks others). The synced `role` is the seat, except a player whose teammate is missing or disconnected is `solo` (all controls). Car id = `car<slot>`, so team color and sort order follow the slot. Players join unseated (watching) and pick on a temporary DOM join screen that closes when they sit and reopens with Esc; the name is remembered in localStorage. Until P2.2, a car follows its first connected occupant's input. `maxClients` = 2 × `race.maxCars` (new key, 8). Lobby messages have their own rate limit (5/s, burst 5).
- D040 (2026-10-04, P2.2): Input merge. Clients always send their full key state; the server keeps only what each player's current role allows (`ROLE_CONTROLS`): Pilot = steer, Engineer = gas + brake, Solo = all, respawn = anyone. Filtering by role on the server (not the client) means a role change (partner leaves, later swap lane) takes effect on the next tick with no client update. A bottom-left role badge shows the role and its keys and flashes when it changes.
- D041 (2026-10-04, P2.3): Multiple cars. Starting grid = rows of two behind the start line along the track curve (`race.gridRowSpacing` 7 m, `race.gridLateral` 3 m), grid position = car slot. Car-vs-car = circles of `car.radius`, resolved after all cars move each tick, in id order: push apart split by weight (lighter moves more), then a bounce impulse with restitution `car.carBounce` (0.4) only when closing; momentum is conserved. Ghosted, respawning and airborne cars pass through. A closing speed ≥ `car.carHitMinSpeed` emits `carHit`. Intended feel change: the 2-car golden replay hash moved a71bcb87 → 27703279 (the bots touch); lap windows unchanged.
- D042 (2026-10-04, P2.4): Disconnect/rejoin uses Colyseus 0.18 `onDrop` + `allowReconnection(net.reconnectSeconds)` + `onReconnect`; timeout → `onLeave`. A dropped player keeps slot and seat with `connected = false`; `effectiveRole` makes the partner solo meanwhile; inputs reset on drop and return so a held key never sticks. Client: the SDK's automatic reconnection covers blips (status "reconnecting…"); for a closed/reloaded tab the reconnection token and leave time are saved in localStorage on `pagehide` and tried on load while inside the window, else a fresh join. Two tabs on one PC share that storage: a tab whose token belongs to a still-connected session just joins fresh.
- D043 (2026-10-04, P2.5): Networked bots live in `packages/client/src/bot/netBot.ts` (bots are clients; that package has the SDK) and see only synced state: `carStateFromView` (shared) rebuilds a CarState from x/z/y/yaw/speed so the same `botSteer`/`botPedals` drive over the network (speed assumed forward). Each car = Pilot-bot client sending only steer + Engineer-bot client sending only pedals, on every state patch (~30/s, under the input rate limit); the engineer's stuck timer therefore counts patches (≈2× longer than in the headless sim). Laps = start-line crossings after the first (bots start behind the line). Clients register no-op handlers for broadcasts they ignore (else the SDK warns per message). The real-time integration lap makes `npm run verify` take ~1 min; accepted because it is the only end-to-end proof of split control.
- D044 (2026-10-05, P2.6): Latency. The server writes each player's last applied input `seq` into the state (`ackSeq`, sent with the patch that carries the resulting motion); the client times send → echo (smoothed, weight 0.2) and adds `net.interpDelayMs` for "input → screen". The 250 ms input resend keeps the number fresh while idle. Snapshots now sit on a server-tick timeline (offset = min arrival − tick time, relaxing +0.5 ms per snapshot) instead of arrival time — closes the P1 review item. Measured on localhost: 38 ms echo + 50 ms interpolation = 88 ms. Patch rate and interpolation delay were already live-tunable (F2 `net`).
- D045 (2026-10-05, FUN GATE bug): The join screen rebuilt its buttons on every state patch (~30/s), so hover animations restarted (jitter) and human-speed clicks were lost (button replaced between press and release). It now redraws only when its HTML would change. Lesson: DOM UI fed by `onStateChange` must diff before touching the DOM; headless clicks (~1 ms) do not catch this, so browser smoke tests use a slow press (250 ms) with live traffic.
- D046 (2026-10-05, FUN GATE): Answers: steering "a little bit laggy" → add client-side prediction for your own car (P2.8). Fun: yes, but physics feel weird (box-spinning turns, steering response, speed). Fixed vs shuffled teams and other open questions stay open.
- D047 (2026-10-05, P2.8): Physics feel pass from the FUN GATE. New `car.carve` (0.8): each tick the velocity turns with the car by that fraction of the yaw change (× slickGrip on slicks), so turns carve instead of pivoting. New `car.accelCurve` (2): engine pull = accel × (1 − (v/top)^curve), strong until near top speed. Coasting was nearly as strong as braking (19.5 m/s² at 30 m/s) → `car.drag` 0.6→0.2, `car.rollingResistance` 1.5→2 (now 8 m/s²). Steering calmer: `car.maxYawRate` 2.6→2.1, `car.steerRiseRate` 5→4. Drag moved more than the usual 15–30% step because the feedback named it directly. Golden: lap 1 37.40→35.57 s, flying 36.00→34.60 s, windows re-centred (±~5%); 2-car hash 27703279→f1135e86.
- D048 (2026-10-05, P2.8): Client-side prediction for your own car only, as "re-predict from the latest server state each frame" (no input history/rollback): ahead = time since the update + measured input echo (capped by `net.predictMaxMs` 200), whole ticks plus a blend for the fraction, your role's controls from your keys and the rest from the server's applied input; when a new update moves the prediction, the old→new gap fades at `net.predictCorrectionRate` (8/s). Server now syncs vx/vz/vy and the applied input per car. Not predicted: car-vs-car bumps, respawns. Measured in Chrome with a real key press: the turn is visible 14 ms (first frame) after pressing, vs ~88 ms before. A synthetic in-page KeyboardEvent did not reproduce real presses in the browser check (unexplained harness quirk); browser checks use Playwright's trusted key presses.
- D049 (2026-10-05, P2.9): Phase 2 review fixes. Critical: a reconnect now resets the player's input `seq` (a reopened page counts from 1; before, every new input looked stale and the controls stayed dead). Bots wait for the server to confirm each seat and fail loudly on refusal. The real-time bot lap test no longer checks wall-clock lap time (lap times are guarded by the headless golden test). Prediction: real car stats from cars.json, base timed on the tick timeline, hint dropped after a seat change or teleport, per-frame objects reused (`readInto`, cached car id; the sim's per-step event list is still allocated). Cars that appear mid-race start ghosted; locking seats during a race and counting only seats in `maxClients` moved to P3.1. `DEFAULT_TRACK` is one shared constant. Not done (noted): car-vs-car push can leave a car slightly past a wall for one tick; join-screen list rebuilt per patch before its diff. Determinism note: `Math.pow`/`sin`/`cos` may differ between JS engines, so the pinned replay hash holds on V8 (Node, Chrome, Edge); the server is authoritative, so play is unaffected.
- D050 (2026-10-05, P3.1): Race state machine in shared `race/flow.ts`: lobby (free driving) → countdown (cars reset to grid by slot, controls ignored) → racing → results (needs the P3.3 race-over signal) → lobby or rematch (results → countdown). Host = earliest-joined *connected* player, so a dropped host hands over at once and does not get it back on return. Seats lock from countdown until results. Laps 1–10, default 3 (`race.defaultLaps/minLaps/maxLaps`). `maxClients` = 2 × maxCars + `race.maxSpectators` (8) so watchers and held seats cannot lock seated players out. When the room empties it returns to the lobby.
- D051 (2026-10-05, P3.2): Lobby. Default team names live in a new `config/teams.json` (content, read once at start; one name per slot, repeating with a number past the list). Team members or the host may rename a team. Ready is informational: the host can start any time (no forced waiting). Shuffle seats every connected player in random pairs (seeded `Rng(tick + 1)`, ids sorted first so results do not depend on join order); the odd one out drives solo; overflow watches. The bots switch is stored now; bot cars arrive in P3.4. The lobby replaces the P2 join screen, keeps its card look, opens between races, closes on countdown, Esc hides it, and is compact enough for 1280×720 without scrolling.
- D052 (2026-10-05, P3.3): Race rules are pure functions over a `RaceRun` (shared `race/rules.ts`), fed by the sim's checkpoint events only while racing; the run starts at GO so race times exclude the countdown. Places use sectors done + signed fraction into the next sector, so a car still behind the start line on the grid is slightly behind, not a lap ahead. Finish window 30 s after the winner (`race.finishWindowSeconds`), then DNF; the race also ends when everyone is done or no cars are left. Wrong way = moving against the track direction faster than 3 m/s for 1.5 s. Grid: random first race (seeded), then previous results reversed, cars new to the race in front. Places are computed after the phase change each tick (a one-tick "place 0" on the first racing tick was caught by a test).
- D053 (2026-10-05, P3.4): Server bot cars use the same `botInput` as the golden tests, driving both roles. GAME_DESIGN says bots "fill empty cars" without a count; chosen: fill the lowest empty slots until there are `race.botFillCars` (4) cars in total, so a pair of humans still gets a race with traffic but 8-car chaos needs 8 teams. Sitting in a bot's car takes it over (the car stays, no teleport); turning bots off removes them; the switch is refused during a race. The host may start with bots only and watch. A start now needs at least one car of any kind.
- D054 (2026-10-05, P3.5): Spectating is simply "not in a car": the camera follows a car chosen by the client (leader first, auto-cycle 8 s, A/D or ←/→ to switch, manual choice holds for 20 s). Late joiners need no special state (seats are locked, the lobby stays closed until the race ends). Scoreboard gaps are sector time splits (server stores when each car passed each sector), so they are real seconds and need no speed estimate; before the first sector no gap is shown.
- D055 (2026-10-05, P3.6): Results need no new synced state: cars keep their final place, time and best lap through the results phase, and the client builds the table from them. The lobby now opens only in the lobby phase; the results screen covers the results phase (host: REMATCH = start again with the reversed grid, Back to lobby = `host:lobby`). Overall fastest lap is marked ⚡. Awards and points arrive with the league (P9).
- D056 (2026-10-05, P3.7): The load test is its own Vitest project (`npm run test:load`, ~2 min real time) and `verify` / `npm test` name their projects so they skip it. The server keeps per-race tick stats (avg, max, count over the 16.7 ms slot) in the synced state. Investigated a failing "max < half the budget" check: average 0.40 ms, but rare garbage-collection pauses (observed up to ~18 ms via perf_hooks) land inside a tick because the test runs the server and 17 clients in one process. The check is now "average < 25% of the slot and ≤ 0.1% of ticks over it"; the true max is printed every run (seen 6–24 ms). Follow-up: measure the standalone server under real bot clients in P7.
- D057 (2026-10-05, P3.8): Phase 3 review fixes. Critical: a race could never end if nobody finished (idle solo player, stuck bots) → new `race.maxRaceSeconds` (600) ends it with DNFs, and the host gets "⏹ End race" (`host:endRace`: countdown → lobby, racing → results with DNFs). DNFs are ordered by how far they got (was: by car id, which also skewed the next grid). New bot cars are added only between races (no phantom car when a reconnect hold expires mid-race). Results keep every car until the lobby or a rematch. Shuffle includes players whose seat is held. Server logs race end, host-ended races and host changes. Client: Tab/Esc ignored while typing, countdown pop only on a new number, lobby does no rendering while hidden, no wrong-way warning after finishing. Kept as UI constants (not gameplay tuning): spectator cycle timings, "CLOCK OUT!" display time.
- D058 (2026-10-05, P4.1): Cockpit cam. Eye in your seat (Pilot/Solo left, Engineer right), 0.38 m above the body top, 0.45 m behind the car center. Mouse look only with Pointer Lock (click to capture, Esc to release); head yaw ±1.75 rad, pitch ±0.6 rad; with the mouse free the head eases back to straight ahead. Head bob is a damped spring kicked by your car's wallHit / carHit / land events (`camera.headBob` 0.15 m per m/s; 0 turns it off for anyone who gets motion sick) — first value was 100× too small, caught by a test. Only your own car shows a cockpit mesh (low dashboard + windshield frame, one merged draw call). C toggles chase/cockpit, saved in localStorage; watchers always get the chase cam.
- D059 (2026-10-05, P4.2): Head angles are not part of the sim (cosmetic): the room validates, clamps and writes them straight into `PlayerState` (no RaceSim involvement). Clients send at most every `net.headSendMs` (50 ms) and only when the head moved > ~0.5°, so looking at the road costs no traffic; in chase view the head is 0,0. Receivers ease toward the synced angle at 12/s (UI constant) so 20 Hz updates look fluid.
- D060 (2026-10-05, P4.3): Bobbleheads. Faces: `npm run faces` builds the manifest; the game server serves `/faces/*` (express.static, path traversal → 403; Vite proxies in dev); `lobby:setFace` accepts only existing files. Head = one sphere with a wrap-around canvas texture (light "helmet" color, face oval at the front: u = 0.25 is where three.js puts +Z), cover-fit photo or the drawn placeholder (smile + glasses); one material per face shared by all heads. Heads sit above the roof (center 1.82 m) so they read from the chase cam, turn with the synced head angles (+yaw = left, same as the cockpit) and wobble on a bouncy spring driven by the car's acceleration (computed per frame from speed/yaw). Your own head is hidden in your cockpit. Solo cars show a rubber duck; bot cars two placeholder heads. Draw calls: rear wheels merged into one axle mesh (car model 5 draw calls); each head adds 1, so a two-player car is 7 — heads are counted as passengers outside the 6-per-car model budget; /shots still checks the scene budget (chase 12 draws).
- D061 (2026-10-05, P4.4): Gauges have one source (`gaugeText`) and two views: a 512×128 canvas screen tilted on your cockpit dashboard (one draw call, your car only, redrawn at most every 100 ms and only when the text changes) and a DOM panel in chase view.
